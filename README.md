# Chronologix AI

Turn a box of case records — medical records, depositions, incident
reports, and recorded statements — into a **verified, source-cited
chronology** and a **demand-letter draft**, for plaintiff's personal-injury
and civil litigation firms. Every fact traces back to the exact document
page or recording timestamp it came from, and nothing is final until an
attorney signs off.

## What it does today

- **Ingest** documents (PDF/DOCX, with OCR fallback for scanned records) and
  video/audio evidence (transcribed with speaker labels + timestamps).
- **Build a chronology** — a date-ordered timeline of events, each citing
  its source document page or evidence timestamp, generated by Claude and
  designed so a dropped or hallucinated fact is treated as a high-severity
  bug (there's a dedicated accuracy-verification step for exactly this).
- **Flag inconsistencies** across sources (conflicting dates, contradicting
  statements) for attorney review — never resolved silently.
- **Attorney review** — edit any entry (edits are versioned and survive
  regeneration), confirm which evidence is trustworthy, and sign off.
- **Draft a demand letter** from a signed-off chronology — facts only from
  the record, no invented dollar amounts, with `[ATTORNEY: …]` placeholders
  for the legal judgment calls.

See `PLANNING.md` for phase-by-phase status and `docs/architecture.md` for
the full data flow.

## Stack

FastAPI (Python 3.13) backend in `api/`, Next.js (TypeScript) frontend in
`web/`, Supabase (Postgres + pgvector, Storage) for data. Claude for
chronology/flag/demand generation, Voyage AI for embeddings, Deepgram for
transcription.

## Running it locally

### 1. Backend (`api/`)
```bash
cd api
python -m venv .venv
.venv/Scripts/python.exe -m pip install -e ".[dev]"   # Windows; use .venv/bin/python on macOS/Linux
```
Create `api/.env` from `api/.env.example` and fill in:
```
SUPABASE_URL=...            # from your Supabase project settings
SUPABASE_SERVICE_KEY=...    # service role key (NOT the anon/publishable key)
ANTHROPIC_API_KEY=...
VOYAGE_API_KEY=...
DEEPGRAM_API_KEY=...        # only needed for video/audio evidence
TESSERACT_CMD=...           # path to tesseract.exe on Windows; omit if tesseract is on PATH
```
Apply the schema to your Supabase project (the `supabase/migrations/` files,
in order — via `npx supabase db push` against a linked project, or by
running each migration's SQL). Then start the API:
```bash
cd api && .venv/Scripts/python.exe -m uvicorn main:app --reload
```

### 2. Frontend (`web/`)
```bash
npm install --prefix web
npm run dev --prefix web
```
Open http://localhost:3000.

### 3. (Optional) load a demo case
With the API running, populate a complete synthetic example (two documents
→ chronology → flags → sign-off → demand letter):
```bash
cd api && .venv/Scripts/python.exe seed_demo.py
```
All seed data is fictional — no real client information.

## Compliance note

Case documents contain PHI and privileged material. Real client data must
never be committed; all sample/test data is synthetic. Real deployment
(BAA-covered hosting, per-firm access control, audit logging) is future
work — see `PLANNING.md`. The current build uses a placeholder firm and no
end-user auth; it is a working prototype, not a production deployment.

## Development workflow (for contributors using Claude Code)

This repo is built with an Opus-orchestrator / delegated-builder workflow:
`.claude/agents/` defines `builder` (implements one scoped increment),
`code-reviewer` (read-only quality/security gate), `accuracy-verifier`
(read-only check that generated chronologies don't hallucinate or drop
facts — the failure mode that matters most for a tool you're meant to
trust), and `cost-auditor`. `/ship` in `.claude/skills/ship/` runs the
plan → build → review → accuracy-check loop.
